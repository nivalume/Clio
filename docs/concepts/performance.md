# 性能

本页的数字来自仓库里的 `bench/run.ts`，在一个 2 万篇笔记的合成知识库上测量。引擎各阶段的设计见 [[architecture]]，图谱的算法见 [[knowledge-graph]]。

## 测试条件

- **知识库**：`bun bench/gen.ts 20000 <目录>` 生成 20,001 篇笔记、91,024 条链接，其中 714 个链接目标不存在（待写笔记）。笔记分属预设的社区，链接数呈幂律分布，正文中英混合。
- **机器**：4 核 Intel Xeon 2.1 GHz，16 GB 内存，Linux，Bun 1.4.2。引擎用 WebAssembly 版本，和用户实际运行的一样。
- **浏览器**：无头 Chromium，窗口 1440×900，没有 GPU 加速。

## 结果

| 项目 | 结果 | 目标 |
|---|---|---|
| 引擎：解析 20,001 篇笔记 | 8.8 s | |
| 引擎：全库阶段（链接、关系、PageRank、聚类、检查、搜索索引） | 4.3 s | |
| 引擎：首次布局（ForceAtlas2，20,715 个节点，含待写节点） | 7.8 s | |
| 引擎合计 | 20.9 s | ≤ 30 s |
| `clio build` 冷构建（没有缓存） | 70 s | ≤ 3 分钟 |
| `clio build` 热构建（有缓存，内容没变） | 55 s | ≤ 60 s |
| 加一篇笔记后重新构建 | 84 s | |
| 加一篇笔记后的布局变化 | 节点平均移动图宽的 0.12%，只有 1 个节点移动超过 2% | 其余节点基本不动 |
| 图谱视图：打开页面到画出图谱（本机服务，首次 / 有缓存） | 1.5 s / 1.0 s | |
| 图谱视图：拖动和缩放 | 平均 69 帧/秒，95% 的帧在 17.8 ms 内完成 | ≥ 50 帧/秒 |

加一篇笔记后的那次构建，各阶段大致是：读文件并解析 9 s，全库阶段 3.8 s，布局（热启动）2.3 s，逐页生成 HTML 27 s，复制前端和写 `llms.txt` 2 s，Pagefind 建索引 27 s。内容没变的热构建省掉的是最后一步：HTML 页面和上次完全相同时，直接复用上次的搜索索引。

引擎的原生版本和 WebAssembly 版本对同一知识库给出逐字节相同的输出，布局坐标也一样；测试里用 1,500 篇的合成库检查这一点。

## 输出体积

| 文件 | 大小 | gzip 后 |
|---|---|---|
| 一篇笔记的 HTML 页面（中位数） | 9.7 KB | |
| `_clio/zh/graph.json`（图谱的节点、坐标和边） | 3.7 MB | 0.8 MB |
| `_clio/zh/manifest.json`（浏览和标题搜索用的笔记列表） | 4.3 MB | 1.0 MB |
| `_clio/zh/site.json`（首页） | 0.33 MB | 0.08 MB |
| `pagefind/`（全文搜索索引） | 89 MB | 浏览器只下载查询用到的分片 |

首页只取 `site.json`。`manifest.json` 在打开浏览页或搜索框时才取，`graph.json` 只在图谱页取。

## 做到这些的设计

- **每篇笔记只解析一次。** 引擎记住每个文件的内容哈希，内容没变就不重新解析；`clio dev` 和 `clio mcp` 只重读修改时间变了的文件。
- **全库阶段的数据结构是有序的。** 用 BTreeMap 和排好序的数组，输出不依赖哈希表的遍历顺序。PageRank 迭代 40 次；Louvain 每一轮的工作量和边数成正比。
- **布局用 Barnes–Hut 近似。** 斥力用四叉树近似，每次迭代是 O(n log n)。第二次构建从缓存里上次的坐标开始，并限制移动速度，所以新增的笔记落在它的邻居旁边，其余节点几乎不动。一次新增的笔记超过五分之一时，改为完整地重新布局。
- **渲染结果按内容缓存。** Shiki 高亮、KaTeX 公式和图表的 HTML 按内容哈希存在 `node_modules/.cache/clio`，没变的代码块不会再高亮一遍。
- **前端按需取数据。** 正文不打进前端的包。首页、浏览页和图谱页各取自己需要的 JSON，笔记的正文、关系和局部图谱随笔记页面一起取。
- **图谱用 Canvas 绘制。** 屏幕上的节点很多时，画成按颜色合并的小方块；拖动和缩放时移动上一帧的快照，手势停下后再完整重画。只给视口里 PageRank 高的节点标名字，缩得很小时改为显示聚类的名字。

## 瓶颈和下一步

- 热构建的大部分时间在逐页生成 HTML（约 27 s，其中引擎渲染约 10 s）和 Pagefind 建索引（约 27 s）。Pagefind 没有增量模式，任何页面有变化都要重建整个索引。
- 引擎是单线程的 WebAssembly。原生版本可以并行，但默认的安装方式不要求 Rust，见 [[roadmap]]。
- 到 10 万篇时，`manifest.json` 需要按类型拆成几个文件。

## 复现

```bash
bun bench/gen.ts 20000 /tmp/kb20k
bun bench/run.ts 20000 --dir /tmp/kb20k
```

`bench/run.ts` 输出一段 JSON，包含上面表格里引擎、构建和布局稳定性的数字。图谱帧率用无头浏览器在图谱页上拖动和缩放，记录每一帧的间隔。
